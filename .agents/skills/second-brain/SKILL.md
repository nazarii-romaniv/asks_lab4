# Skill: second-brain

Навичка для роботи з Markdown-нотатками в `notes/` (PARA: Inbox, Projects, Areas, Resources, Archives).

## Коли застосовувати
- користувач додає або вставляє сирий текст нотатки;
- просить визначити категорію, теги чи пов’язані нотатки;
- просить короткий підсумок нотатки або групи нотаток.

## Обов’язкові правила
1. **Не вигадувати джерела.** Поле `source` заповнювати лише тим, що вказав користувач; інакше — `"власний конспект"` або `"невідомо"`. Не вигадувати посилання, авторів, цитати, дати.
2. **Зберігати оригінальний зміст.** Не переписувати і не «покращувати» текст автора без прохання. Підсумок — окремо, у розділі «Короткий зміст», з позначкою, що він згенерований.
3. **Не видаляти й не переміщати файли без явного підтвердження користувача.** Спочатку запропонувати дію й чекати відповіді «так».
4. **Не виходити за межі проєкту.** Змінювати лише файли в цьому репозиторії.
5. **Не записувати чутливі дані** (паролі, токени, медичні, фінансові, персональні дані третіх осіб). Якщо вони є — попередити користувача.
6. **Зв’язки пропонувати тільки на наявні нотатки.** Перед додаванням `[[Назва]]` перевірити, що нотатка з таким `title` існує в `notes/`.

## Класифікація (PARA)
| Категорія | Критерій | `type` |
|---|---|---|
| Inbox | не опрацьовано, невідомо куди | `inbox` |
| Projects | активний результат з дедлайном | `project` |
| Areas | довготривала сфера відповідальності без кінцевої дати | `area` |
| Resources | тематичний матеріал для повторного використання | `resource` (`moc` — для карт змісту) |
| Archives | завершене або неактивне | `archive` |

Завжди пояснюй у одному реченні, **чому** обрано саме цю категорію.

## Формат нотатки
Використовуй `templates/note-template.md`. Обов’язкові поля frontmatter: `title`, `created`, `updated`, `type`, `status`, `tags`. Теги — нижнім регістром, латиницею або кирилицею, без пробілів (через дефіс), 2–5 штук.

## Алгоритм
1. Прочитай нотатку та список наявних `title` і тегів у `notes/`.
2. Визнач категорію і `type`; поясни вибір.
3. Запропонуй 2–5 тегів (переважно наявні).
4. Запропонуй зв’язки з наявними нотатками.
5. Сформуй короткий підсумок (до 3 речень) без нових фактів.
6. **Нічого не записуй, доки користувач не підтвердить** (крім випадку, коли він прямо просив створити файл).

## Прогресивне розкриття
Тримай у контексті лише цей файл. Читай інші файли (`docs/architecture.md`, окремі нотатки) тільки тоді, коли вони потрібні для поточного кроку.

## Журнал запропонованих змін (в кінці кожної відповіді)
```
### Журнал змін
| # | Файл | Дія | Причина | Потребує підтвердження |
|---|------|-----|---------|------------------------|
| 1 | notes/Inbox/… | створити | нова нотатка | ні |
| 2 | notes/Resources/… | додати тег `cloud` | тематичний збіг | так |
```
